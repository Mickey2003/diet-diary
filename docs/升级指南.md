# 升级指南（v0.7 / v0.6 → v0.7.1；步骤通用，历史版本变化见文末附录）

> 原则：只替换代码，**不要覆盖** `backend/.env`、`backend/data/`（数据库）、`backend/uploads/`（照片）。
> 数据库表结构会在后端启动时自动迁移（v0.7.1 新增 `users.is_approved`、`sound_files.is_system`；v0.7 新增 `inbox_messages.extra` 与 `sound_files` 表；提醒音效预设 wav 会在首次启动时生成到 `backend/data/sounds/`），无需手动执行 SQL。**已有用户全部视为已审核**，不受影响。
> Android App **建议更新到 1.3.1**：1.3.0 修复后台播放就餐提醒音效，1.3.1 修复 App 内上传自定义音效时弹出的是“选图片”而不是“选音频”。不更新 App 也能使用其余全部功能。

## 一、Windows Server + 宝塔面板

1. **备份**（1 分钟，强烈建议）
   - 宝塔「Python 项目管理器」→ 停止 `diet-diary` 项目（或停止 Windows 服务 `DietDiary`）。
   - 复制 `D:\wwwroot\diet-diary\backend\data\` 和 `backend\uploads\` 到别处（数据库为 `diet.db` 及同名 `-wal`、`-shm` 文件，一起复制）。
2. **上传新包**：把 `diet-diary-windows-bt-v0.7.1.zip` 上传到 `D:\wwwroot`，解压到临时目录（例如 `D:\wwwroot\diet-diary-new`）。
3. **替换代码**（用宝塔文件管理器或资源管理器）：
   - 删除旧的 `diet-diary\backend\app`，把新包的 `backend\app` 复制进去；
   - 用新包的 `backend\requirements.txt` 覆盖旧文件；
   - 删除旧的 `diet-diary\frontend\dist`，把新包的 `frontend\dist` 复制进去；
   - 覆盖 `windows\`、`docs\`、`README.md`。
   - **不要动** `backend\.env`、`backend\data`、`backend\uploads`。
4. **安装新增依赖**（本次没有新增第三方库，但执行一次无害）：项目「终端」或「模块管理」执行  
   `pip install -r requirements.txt`  
   （若是 NSSM 方式：`backend\.venv\Scripts\pip install -r backend\requirements.txt`）
5. **可选新配置**：本次没有新增 `.env` 项。就餐提醒音效在网页「健康 → 个性化餐单」或「通知推送」页按用户设置。若 Nginx 反代之前设置了 `proxy_read_timeout 300s`，请改为 **`proxy_read_timeout 300s`**（餐单生成可能需要 1–3 分钟，见 `windows\nginx-reverse-proxy.conf`）。
6. **启动**：在 Python 项目管理器点「启动」（或 `net start DietDiary`）。看日志应出现 `[db] 迁移完成：users.is_approved, sound_files.is_system`（从 v0.6 升级还会有 `inbox_messages.extra`；只在首次启动出现一次）与 `Uvicorn running on http://127.0.0.1:8000`。
7. **验证**：浏览器强制刷新（Ctrl+F5）打开站点 → 登录 → 点底部「健康」应直接看到「个性化餐单」；在「就餐提醒音效」卡片点「试听」有声音、点「发送测试提醒」后「消息中心」出现一条可点开的提醒，详情页有「试听音效」按钮。
8. **回滚**（如有问题）：停止项目 → 用备份的旧 `backend\app` 与 `frontend\dist` 覆盖回去 → 启动。数据库多出的列与表不影响旧版本运行。

> Nginx 配置不需要改动。若之前没加过 `proxy_read_timeout 300s` / `client_max_body_size 30m` / `X-Forwarded-Proto`，请参考 `windows\nginx-reverse-proxy.conf` 补上。

## 二、Linux（systemd + Caddy，由 deploy/install.sh 安装）

```bash
cd /path/to/diet-diary
sudo systemctl stop diet-diary
cp -a backend/data backend/data.bak-$(date +%F)        # 备份数据库
cp -a backend/uploads backend/uploads.bak-$(date +%F)  # 备份照片（可选，较大）

# 方式 A：git
git pull
# 方式 B：zip
unzip -o /tmp/diet-diary-v0.7.1.zip -d /tmp/dd && rsync -a --exclude '.env' --exclude 'data' --exclude 'uploads' /tmp/dd/diet-diary/ ./

source backend/.venv/bin/activate && pip install -r backend/requirements.txt && deactivate
cd frontend && npm install && npm run build && cd ..
sudo systemctl start diet-diary
sudo journalctl -u diet-diary -n 30 --no-pager    # 应看到 [db] 迁移完成 与 Uvicorn running
```

## 四、本次版本变化一览

### v0.7.1

- **注册审核**：新注册账号默认需要管理员在「用户管理」中点「通过」后才能登录（「拒绝」= 删除该账号）；有人注册时管理员收件箱会收到「管理通知」。开关在「用户管理」页：「新注册账号需管理员审核」，**默认开启**；关闭则恢复“注册即登录”。升级前已存在的账号全部视为已审核。
- **系统预设音效管理（管理员）**：在「通知推送 / 健康 → 就餐提醒音效」中，管理员可上传系统预设音效（所有用户可选）、重命名、删除；6 个内置合成音效可重命名、可对用户隐藏（不可删除）。普通用户可重命名自己上传的音效。
- 「我的」页底部版本号改为统一常量（v0.7.1），不再滞后。
- 统计页空状态删除“可运行 python -m app.seed”开发者提示，改为引导去记录一餐。
- App 1.3.1：`<input accept="audio/*">` 在 App 内打开系统音频选择器，不再只让选图片。

### v0.7

- **「健康」页默认打开「个性化餐单」**，标签顺序改为：个性化餐单 / 我的档案 / 体质自测；支持 `/health?tab=profile` 直达。
- **餐单页面溢出修复**：方案说明里的「替换建议」「购物清单」「小贴士」等长文本全部改为自动换行列表，页面不再被撑宽。
- **重复 / 残缺餐单修复**（根因见 `docs/AI_LOG.md` 案例 17）：
  - 后端对模型返回做**完整性校验**（每天都有餐、每餐都有菜，否则重试/报错），并把**校验补全后的结构**入库，前端不再遇到 `undefined.map`；
  - 同一用户**同时只允许一次生成**（第二次请求返回 409「餐单正在生成中」），前端按钮生成期间禁用；
  - 前端生成请求超时从 90 秒延长到 4 分钟，超时不再造成“前一次其实成功了、又生成了一份”的重复；
  - 已经存在的残缺餐单会显示「数据不完整，可删除后重新生成」而不是白屏。
- **消息中心详情**：点消息进入详情页，AI 生成的内容（周报、餐单说明等）按 Markdown 渲染；有关联页面时显示「前往查看」。
- **就餐提醒音效**：到餐单里的就餐时间（可提前 N 分钟）播放提示音，6 种服务器预设 + 用户上传（mp3/wav/ogg/m4a，≤3 MB，每人 ≤20 个），可选餐次、音量、震动，可发送测试提醒。网页前台由页面播放；服务器同时按餐单时间写入收件箱并推送到 App，App 1.3.0 在后台也会播放。
- 模型端 `meal_plan` 任务输出上限提高到 8000 tokens，避免多日餐单被截断。

## 五、常见升级问题

| 现象 | 处理 |
|---|---|
| 启动报 `no such column: inbox_messages.extra` | 说明代码是新版但迁移没跑：确认 `backend/app/db.py` 已是新版本并重启一次；迁移在 `init_db()` 中自动执行 |
| 生成餐单提示「餐单生成失败：timeout」或 Nginx 504 | 反向代理超时太短：Nginx `proxy_read_timeout 300s;`（Caddy 默认无超时，无需改） |
| 生成餐单提示「餐单正在生成中，请稍候…」 | 上一次生成还没结束，等待即可，前端会自动轮询并在完成后显示 |
| 网页里到点没有声音 | 浏览器要求用户与页面有过交互后才允许自动播放：打开页面后点一下任意位置即可；App 内无此限制 |
| App 后台收到提醒没有声音 | 需更新 App 到 1.3.0；并确认系统「就餐提醒」通知渠道未静音、App 已关闭电池优化 |
| 页面还是旧样子 | 浏览器/App 缓存了旧 `index.html`：Ctrl+F5；App 内菜单「刷新」或「清除缓存与登录」 |
| 新用户注册后提示“等待管理员审核” | 这是 v0.7.1 默认行为：管理员在「用户管理」点「通过」；不需要审核可在同页关闭「新注册账号需管理员审核」 |
| App 里上传音效弹出的是相册 | App 版本低于 1.3.1，请更新 App；或先在电脑浏览器上传 |

## 附录：v0.5 → v0.6 变化一览

- 每个菜品新增**估算热量**：模型给值 → 本地常见菜品表兜底 → 可手动修改；条形码商品按营养成分表 × 净含量换算。时间线、详情、统计（日均、每日柱状、餐次占比）、周报均展示，所有位置标注"估算"。
- 模型分**快速 / 质量**两档：查询规划、结果解释、记忆抽取、分享文案、餐单"换一换"走快速模型；周报、餐单生成走质量模型；每类任务设置输出长度上限，明显缩短等待。
- 图表图例重叠修复（滚动图例、自适应布局、窄屏饼图图例改横向）。
- 界面美化：骨架屏、空状态、卡片与间距统一、登录页、时间线卡片、统计 KPI 瓷片等。
- `requirements.txt` 补齐 `pyotp`、`qrcode`、`tzdata`。

| 现象 | 处理 |
|---|---|
| 启动报 `no such column: meal_items.kcal` | 说明代码是新版但迁移没跑：确认 `backend/app/db.py` 已是新版本并重启一次；迁移在 `init_db()` 中自动执行 |
